# 创建独立的行业简报项目

收到新行业主题后，完成独立项目的配置和验证。以模板同级目录为例：

```bash
mkdir ../new-industry-brief
git ls-files --cached --others --exclude-standard -z \
  | tar -cf - --null -T - \
  | tar -xf - -C ../new-industry-brief
cd ../new-industry-brief
git init
npm ci
cp .env.example .env
```

把目录、npm 包名及锁文件中的项目名称改成新项目名称。同机部署多个项目时，各项目使用自己的 Compose 项目名、镜像名前缀、域名和端口。

1. **确定选题。** 根据用户给出的行业主题推断目标读者，设置刊名、描述和主办方。编辑 `src/publication/identity.ts` 和 `src/publication/editorial-profile.ts` 中的收录范围、栏目、评分和写作要求。用户未指定栏目时，设计 **3 个固定栏目**，为每个栏目写明收录边界、证据要求和篇幅。将模板的示例栏目替换为实际栏目，未要求的轮动栏目设为空。
2. **找信源。** 用户未指定信源时，联网找 **3–5 个**与主题相关的公开入口，优先原始发布者。实际请求入口，抽查可解析的标题、日期、摘要或正文、原文链接。把选定的入口、格式及栏目名称写入 `src/publication/sources.ts`。用户只指定其中一项时，保留其要求并自动完成另一项。
3. **接入并验证。** 为项目创建独立空库，按 `.env.example` 填本地设置，运行 `npm run db:migrate` 和 `npm run sources:setup`。信源安装后处于暂停状态。验证通过后才在后台启用。入口不可用时，继续找替代入口或在该项目的 `src/publication/source-adapters.ts` 加适配器并试采。交付时列出各信源的验证结果。已经初始化的项目通过后台更新编辑配置。
4. **出一份样刊。** 在独立测试库走一遍采集、相关性筛选、事实归组、生成及发布，核对栏目、来源链接和发布结果。抽查一条无关材料，以及同一事件的第二篇报道。测试可使用本地模拟模型和公开信源样本，交付时说明实时采集和模型调用各验证到了哪一步。
5. **交付。** 说明项目位置、栏目和信源清单。说明本地或部署所需的数据库、站点地址、管理员密码、签名密钥、模型及可选的 SMTP。执行 `npm run check` 和 `npm run test:browser`，测试库配置见项目 README。

## 数据库初始化和后续升级

空库用 `database/migrations/0001_baseline.sql` 建表、创建索引和约束。应用记录已执行脚本与校验和，重启时跳过已执行脚本。派生项目上线后修改表结构时，再新增编号迁移升级有数据的数据库。

可直接交给 AI 的一句话示例：

> 基于此模板，创建一个面向 AMC 从业者的法律与不良资产处置简报。
