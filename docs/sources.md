# 信源接入

每个刊物的选定入口写在 `src/publication/sources.ts`。运行 `npm run sources:setup` 保存候选并执行采集验证。重复运行会复用已有入口，保留已验证信源的设置。后台「信源管理」提供试采、人工配置和启停。

| 采集格式   | 入口要求                                                           |
| ---------- | ------------------------------------------------------------------ |
| RSS / Atom | 带标题、原文链接和明确日期的订阅文档                               |
| JSON       | 最多 100 条的数组，每条含 `title`、`url`、`excerpt`、`publishedAt` |
| 网页       | 公开 HTTPS 列表，日期与链接位于同一条目。需要正文时开启详情读取    |
| 手工       | 通过后台录入标题、原文链接、来源、日期及摘要                       |

验证与采集使用相同的列表解析入口。遇到站点自有的接口响应或独特页面结构，在派生项目的 `src/publication/source-adapters.ts` 注册限定域名和路径的适配器。可通过 `request` 指定公开请求地址和选项，`parse` 返回统一条目。详情页需要特殊处理时，注册限定原文域名及路径的详情适配器，并使用传入的请求函数。采集模块继续负责访问约束、时间窗口、去重、采集记录和退避。公开站点适配应保留原文链接，并为缺少日期的条目留空。

采集任务只处理已启用、验证通过且到达计划时间的信源。更换采集入口会暂停原配置，重新验证后可以再次启用。信源栏目范围可限制该来源参与的固定栏目。
